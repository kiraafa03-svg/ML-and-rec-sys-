# Аудит решения-примера

Источник: [exam, commit e7895a18e57d8111456cead185a0216d3eec9d93](https://github.com/redlymood/Machine-Learning-and-Recommender-Systems/tree/e7895a18e57d8111456cead185a0216d3eec9d93/exam).
Контрпримеры выполнены в облачной среде 25.10.2026. Это синтетические проверки
программных свойств. Без исходных CSV не измерены частота дефектов и изменение
реального MAP@5. Чужие экспериментальные результаты не выдаются за свои.

| Проблема | Контрпример и полученный результат | Исправление в этом проекте |
|---|---|---|
| Временная утечка через неделю начала передачи | Эфир `[cutoff−1, cutoff+9)`, просмотр `[cutoff, cutoff+9)`: screen=0.9; исходный пайплайн относит просмотр к train неделе 20, хотя весь просмотр на неделе 21 | Сначала обрезать viewing intervals по train cutoff, затем join |
| Холодный user ID отсутствует в глобальном массиве | `users=[10,20]`, requested=15 → AssertionError; requested=30 → IndexError в исходном `predict.py` | Проверка bounds и equality; неизвестный ID получает общий fallback |
| Поиск по неотсортированным концам эфиров | Эфиры `[0,100)` и `[10,20)`, просмотр `[30,40)`: исходный join пропускает первый эфир | Поиск по неубывающему prefix maximum концов; после него точный overlap filter |
| Пустой join | Ни одного положительного пересечения → `need at least one array to concatenate` | Генератор возвращает пустой результат; counts и fallback обрабатывают его |
| Риск двойного учёта сессий | Две одинаковые сессии `[0,60)` на эфире `[0,100)` дают сумму 1.2, уникальное покрытие 0.6 | Явные `union`/`sum`; по умолчанию union, решение записано в manifest |

Последний пункт — различие семантики и возможный риск, а не доказательство
ошибки скрытого оценщика Kaggle. Политика суммирования может быть осмысленной,
если она соответствует определению host. Смена политики меняет разметку и
требует нового отдельного поиска.

Дополнительные решения:

- Точные дубли эфиров удаляются по `(channel,start,duration,show)`.
  Конфликтующие программы с одинаковыми channel/start не стираются молча.
- Длинные user ID не преобразуются в float; сохраняются исходные значения и
  порядок строк template.
- Независимый пересчёт AP подтверждает пример 0.71; формулу AP в примере не
  объявляем ошибочной.
- После 150 подборов на одном holdout максимум называется selection score.
  Перекрывающийся дополнительный временной срез не выдаётся за независимый test.
- Совпадение автоматических тестов не выдаётся за личную проверку студента.

Регрессии находятся в `exam/tests/test_core.py`.
